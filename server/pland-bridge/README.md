# Plan-D → AranChat (pland-bridge)

Plan-D ยิง webhook ("กริ่ง": เกิดอะไรกับรายการ id ไหน) → bridge ตรวจลายเซ็น/กันซ้ำ → อ่านรายละเอียดด้วยบัญชีบริการ
→ ส่งการ์ดเข้าห้องแจ้งเตือนผ่าน `/api/notify` (key ระบบ "Plan-D")

| เรื่อง | เหตุการณ์ Plan-D | ห้อง | รายละเอียด |
|---|---|---|---|
| แจ้งลา | leave.* | room:pland-leave | ผู้ลา หน่วยงาน ประเภท วันที่ จำนวนวัน |
| ไปราชการ | travel_request.* | room:pland-travel | ผู้ขอ เรื่อง สถานที่ วันเวลา พาหนะ |
| แจ้งซ่อม | asset_maintenance.* | room:pland-repair | **แบบสั้น** (API v1 ไม่มีเส้นอ่านคำขอซ่อม) |
| ห้องประชุม | resource_booking.* (meeting_room) | room:pland-meeting-room | ห้อง เวลา หน่วยงาน (+ผู้จอง/วัตถุประสงค์ ถ้าได้ชั้นลึก) |
| ใช้รถ | resource_booking.* (vehicle) | room:pland-vehicle | รถ เวลา (+ผู้จอง/วัตถุประสงค์) |
| ประชุม | meeting.create/update | room:pland-meeting | เรื่อง เวลา สถานที่ จำนวนผู้เข้า |
| หนังสือเข้า | — ยังไม่มีใน API v1 | room:pland-saraban | รอ Plan-D (รับ correspondence./saraban./document.* อัตโนมัติ) |

## สรุปประจำวัน (`daily.mjs`)

ทุกวัน 09:00 น. ส่งการ์ด "วันนี้" เข้าห้องตามเรื่อง (ห้องเดียวกับแจ้งเตือนรายเรื่อง): 🏢 ห้องประชุม · 🚗 ใช้รถ · 📅 จองอื่น ๆ · 🏖️ ลา · 🚐 ไปราชการ · 👥 ประชุม
- รายการที่คาบเกี่ยววันนั้น (ลาต่อเนื่อง / จองข้ามวัน รวมด้วย) · ไม่นับที่ยกเลิก/ไม่อนุมัติ · ⏳ = ยังรออนุมัติ
- เรื่องที่วันนี้ไม่มีรายการ ไม่ส่ง · ตั้งเวลา/วัน/เรื่อง: `DAILY_*` ใน `.env` (ดู `.env.example`)
- ดูล่วงหน้า: `node bridge.mjs --daily --date 2026-11-23` (พิมพ์) · ส่งจริงทันที: เพิ่ม `--send`

## ถามจากแชท (`query.mjs`): `/room` ห้องประชุม · `/car` รถ

พิมพ์ในแชทกับ "ARANKUB AI" หรือในห้องแจ้งเตือน · เมนูบอท "📅 Plan-D ▸" → 🏢 ห้องประชุม · 🚗 รถ · 🏖️ ใบลา · 🚐 ไปราชการ · 🔗 Plan-D ของฉัน (แต่ละปุ่มเปิดการ์ดเลือกวันจากปฏิทิน)
- `/leave [วัน]` ใครลา: แชทส่วนตัว = คนที่เชื่อม /pland และ Plan-D ให้เห็นใบลาหน่วยงาน (หน่วยตัวเอง) หรือทั้งองค์กร · ห้อง = เฉพาะห้องแจ้งลา (LEAVE_TO)
- `/travel [วัน]` ใครไปราชการที่ไหน (ทุกคนดูได้)
- `/room เลือกวัน` → การ์ดมีปุ่ม 📅 เลือกวันที่ (ปฏิทินในแอป) → ได้การ์ดตารางของวันนั้น (การ์ดตารางมีปุ่ม "เลือกวันอื่น" กดซ้ำได้)
- `/room` วันนี้ · `/room พรุ่งนี้` · `/room ศุกร์` · `/room จันทร์หน้า` · `/room 25/11` · `/room 25 พ.ย.`
  → ตารางใครจองอะไร เวลาไหน + ห้องที่ว่างทั้งวัน + ช่วงที่ยังว่างของแต่ละห้อง (เวลาราชการ `WORK_START`–`WORK_END`, ค่าตั้งต้น 08:00–16:30)
- `/room 25/11 13:00-15:00` → ห้องไหนว่าง / ไม่ว่าง (จองเรื่องอะไร) ช่วงนั้น
- Plan-D API ไม่มีรายชื่อห้อง/รถทั้งหมด → รวบรวมจากการจอง 3 เดือนก่อน–2 เดือนหน้า · ห้องที่ไม่เคยถูกจอง เพิ่มเองใน `.env`: `ROOM_LIST=…` `VEHICLE_LIST=…`
- ทดลองบนเครื่อง: `node bridge.mjs --ask room "พรุ่งนี้ 13:00-15:00"`

## เส้นทางแจ้งเตือน 3 แบบ (`routes.mjs`)

| เรื่อง | 1. เจ้าตัว | 2. ห้องกลุ่มงาน | 3. ห้องตามเรื่อง |
|---|---|---|---|
| 🏖️ ลา | ผลอนุมัติ/ไม่อนุมัติ/ยกเลิก | ยื่นใหม่ · อนุมัติ · ยกเลิก | ทุกจังหวะ (งานบุคคล) |
| 🚐 ไปราชการ | ผล + ผู้ร่วมเดินทาง | ยื่นใหม่ · อนุมัติ · ยกเลิก | ทุกจังหวะ |
| 🚗 ใช้รถ / 🏢 ห้องประชุม | ผลการจอง | – | ทุกจังหวะ |
| 👥 ประชุม | – | – | สร้าง · แก้ไข |
| 🔧 แจ้งซ่อม | อนุมัติ · เริ่มซ่อม · เสร็จ* | แจ้งใหม่ · เสร็จ* | ทุกจังหวะ |
| 📨 หนังสือเข้า | ทุกจังหวะ* | ทุกจังหวะ* | ทุกจังหวะ* |

\* ต้องรู้ "ใคร/กลุ่มงานไหน" — Plan-D API ยังไม่เปิดแจ้งซ่อม/หนังสือ: ตอนนี้ได้แค่ห้องตามเรื่อง (แบบสั้น)
พอ Plan-D เปิด ใส่ `REPAIR_DETAIL_PATH` / `DOC_DETAIL_PATH` ใน `.env` (คาดชื่อฟิลด์ requesterName · requesterOrgUnitName · assetName · problem ·
subject · fromName · recipientName(s) · recipientOrgUnitName — ถ้าชื่อไม่ตรง แก้ `fieldsFor` ใน bridge.mjs) · หนังสือเข้ารับชื่อเหตุการณ์ `correspondence.*` / `saraban.*` / `document.*`

- **ห้องกลุ่มงาน** (`units.mjs`): สร้างเองเมื่อกลุ่มงานมีเรื่องครั้งแรก "👥 Plan-D · <กลุ่มงาน>" (bot เจ้าของห้อง) · ชวนคนที่เชื่อม `/pland` แล้วและอยู่กลุ่มงานนั้น
  (ตอนสร้าง + ตอนเชื่อมทีหลัง) · ผู้ดูแลเพิ่ม/ลบคนได้ · `UNIT_ROOMS=off` ปิด
- ปรับตาราง: สร้าง `routes.json` เฉพาะส่วนที่เปลี่ยน เช่น `{ "vehicle": { "unit": ["approve"] } }` แล้ว `pm2 restart pland-bridge`

## แจ้งเตือนรายบุคคล (`personal.mjs`)

เชื่อมแบบสมัครใจ (opt-in) — ใครไม่เชื่อมก็ไม่ได้รายบุคคล (ยังได้ในห้องตามปกติ)

1. ผู้ใช้พิมพ์ **`/pland`** ในแชทกับ "ARANKUB AI" (หรือกดเมนู 🔗 Plan-D ของฉัน / ปุ่มในการ์ดชวน) → ปุ่มเชื่อมบัญชี
   (ลิงก์ใช้ครั้งเดียว · จาก /pland 10 นาที · จากการ์ดชวน 7 วัน)
2. เข้าสู่ระบบที่หน้า Plan-D ด้วยรหัสเดิม (OAuth + PKCE) → bridge อ่าน `/me` + ทะเบียนบุคลากรของตัวเอง แล้ว**เพิกถอน token ทันที** (ไม่เก็บ)
3. **ยังไม่เชื่อมจนกว่าเจ้าของแชทกดยืนยัน** — การ์ด "ยืนยันการเชื่อมบัญชี Plan-D" แสดงชื่อ/หน่วยงานจาก Plan-D + ปุ่ม ✅ ใช่ ฉันเอง / ❌ ไม่ใช่ฉัน
   (กดได้เฉพาะเจ้าของแชท ภายใน 30 นาที) — ลิงก์ที่ถูกส่งต่อให้คนอื่น login จึงเชื่อมผิดคนไม่ได้
   · บัญชี Plan-D เดียวกันเชื่อมกับแชทอื่นอยู่ → การ์ดเตือน · ยืนยันแล้วย้ายมา + แจ้งบัญชีเดิม

ชวนเชื่อม: `scripts/29-pland.sh invite all` (ทุกบัญชีแชทที่ผูก AranKub) หรือ `invite @a:arankub.com,@b:arankub.com`
— ข้ามคนที่เชื่อมแล้ว/เพิ่งชวนภายใน 7 วัน (`--force` ชวนซ้ำ)

| เรื่อง (event ใน AranChat) | ใครได้ | เมื่อ |
|---|---|---|
| `me.leave` ใบลาของฉัน | ผู้ลา | อนุมัติ / ไม่อนุมัติ / ยกเลิก / ถอนอนุมัติ |
| `me.travel` ไปราชการของฉัน | ผู้ขอ + ผู้ร่วมเดินทาง (ต้องมี hr.travel.read.team) | อนุมัติ / ไม่อนุมัติ / ยกเลิก |
| `me.booking` การจองห้อง/รถของฉัน | ผู้จอง (ต้องมี bookings.read.details) | อนุมัติ / ไม่อนุมัติ / ยกเลิก |
| `team.leave` ใบลาใหม่ในหน่วยงาน | คนที่เปิด `/pland ทีม` และ Plan-D ให้เห็นใบลาหน่วยงาน (unit = หน่วยงานตัวเอง · agency = เลือกทุกหน่วยได้) | ยื่นใบลา |

- จับคู่ด้วย**ชื่อ-นามสกุล** (API ไม่ส่งรหัสบุคลากรมากับใบลา/การจอง) — ตัดคำนำหน้า/ช่องว่างก่อนเทียบ
- กันส่งผิดคน: ใน Plan-D มีคนชื่อ-นามสกุลเดียวกัน → ปิดรายบุคคลของคนนั้น (บอกเจ้าตัว) · ชื่อเดียวกันเชื่อมไว้ 2 บัญชีแชท → ไม่ส่ง
- ผู้อนุมัติตัวจริงไม่รู้จาก API — ใช้ `team.leave` แทน · แจ้งซ่อม/ประชุม/งาน ไม่มีชื่อผู้เกี่ยวข้องใน API → ไม่มีรายบุคคล
- คำสั่ง: `/pland` (สถานะ/เชื่อม) · `/pland ทีม หน่วย|ทั้งหมด|ปิด` · `/pland เชื่อม` (อ่านสิทธิ์ใหม่) · `/pland เลิก`
- ผู้ใช้ปิดรายเรื่องได้เองในแชทกับบอท ("ตั้งค่า")

## ติดตั้ง
1. ผู้ดูแล Plan-D: ตั้งค่า → แอปภายนอก → สร้างแอป → แท็บแจ้งเหตุการณ์ เพิ่มปลายทาง `https://chat.arankub.com/api/pland/webhook`
   ติ๊กเหตุการณ์ตามตาราง → ได้ความลับ → `PLAND_WEBHOOK_SECRET`
   แอปเดียวกันนี้ใส่ Redirect URI `https://chat.arankub.com/api/pland/callback` + scope `openid profile hr.personnel.read hr.leave.read` → `PLAND_CLIENT_ID`
2. ผู้ดูแล Plan-D: แท็บบัญชีบริการ → สร้าง + มอบบทบาทตามสิทธิ์ใน `.env.example` → `PLAND_SERVICE_CLIENT_ID/SECRET`
3. หน้าจัดการแจ้งเตือน AranKub: เพิ่มระบบ "Plan-D" → `ARANCHAT_KEY`
4. `cp .env.example .env && chmod 600 .env` แล้วใส่ค่า
5. `scripts/29-pland.sh all` (สร้างห้อง + pm2 + ingress) → เชิญเจ้าหน้าที่เข้าห้อง → `scripts/29-pland.sh sample`
6. Plan-D หน้าทะเบียนแอป → "ส่งทดสอบ" → `pm2 logs pland-bridge` ต้องเห็น "ได้รับเหตุการณ์ทดสอบจาก Plan-D ✓"

ทดสอบบนเครื่อง: `node bridge.mjs --sample` · การ์ดรายบุคคล: `node bridge.mjs --sample --to @payang:arankub.com [--send]` · `PUBLIC_BIND=127.0.0.1:3299 PLAND_WEBHOOK_SECRET=x node bridge.mjs --dry-run`
แล้ว `PLAND_WEBHOOK_SECRET=x node ~/plan-d-starter/plan-d-app.mjs webhook http://127.0.0.1:3299/api/pland/webhook --type leave.approve`
